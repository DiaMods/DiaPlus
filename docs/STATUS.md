Last audited against Dia 1.46.0, build 86064, on 2026-08-28. Builds 85660 and 85823 remain in the guarded patch table.

## Verified on this Mac

- The separately signed clone uses **local.rttm.dia**, an isolated profile, an isolated Keychain label, and does not alter official Dia. Installs now prefer the available Developer ID Application identity, giving TCC/Keychain a stable designated requirement across rebuilds instead of a changing ad-hoc CDHash.
- Anonymous local setup survives relaunch without a Dia account. The Account pane's stub identity is a local dependency object, not a Dia sync account.
- Native New Chat reaches **codex:gpt-5.6-luna** through the deployed bridge. A complete Luna text stream, reasoning stream, and typed native tool call passed end to end.
- Codex Luna/Terra/Sol, Apple Foundation Models, OpenAI Responses, Ollama, and custom OpenAI-compatible provider adapters are implemented. Apple on-device structured generation with Dia tool schemas passes on this Mac. Private Cloud Compute is detected but marked unavailable with a specific explanation because an ad-hoc personal build cannot obtain Apple's managed `com.apple.developer.private-cloud-compute` entitlement; it no longer fails as a generic helper exit. OpenAI/Ollama protocol behavior passes fixtures.
- The model catalog, Developer menu, and native toolbar picker are installed. The toolbar control refreshes in place after the bridge catalog becomes available, draws a compact selected-model label, and stays transparent until the command bar completes layout so it does not flash offscreen. Placement is context-aware: before attachments in side chat and immediately before the microphone on New Tab. A debounced window-update observer restores it whenever Dia replaces the command bar. Developer actions open the local routing editor, model/tool dashboard, diagnostics folder, and Dia's native webpage inspector. Dia 1.46's private Prompt Tools constructor is not invoked because it requires an unavailable production task-local dependency context. Provider keys are stored separately with mode 0600 and are never returned by the settings API or exposed to the Codex subprocess.
- Native tool schemas are passed through dynamically. Dia's `ToolSearch` loads deferred tools without a fixed allowlist; if a weaker model calls one too soon, the bridge deterministically performs the loader step and permits the real call once Dia presents its schema. The persistent inventory distinguishes native, local override, on-demand, and blocked routes. Provider reasoning token spacing is preserved, and progress narration is removed from completed answer text.
- Native response formatting is retained. Markdown table syntax renders through Dia's existing table view. Math/science turns load Dia's `latex-formatting` skill, and common local-model delimiter mistakes are normalized to Dia's exact inline/block markers before its bundled SwiftMath views render them.
- Local replacements cover public web search/fetch, imported people lookup, and memory. Search/fetch notify Dia's original presentation callback, rendering native “Searched the web” and “Read link” cards, while their results execute on localhost. Completed results are made explicit to weaker Chat Completions models so they do not repeat a successful call. Dia product-knowledge tools are suppressed so they cannot restore a Dia-service dependency.
- Local Memory imports isolated-profile history and native page results, captures chat turns, derives durable plans/projects/preferences/interests/facts with source provenance, automatically recalls relevant Memories, and performs hybrid FTS/on-device semantic search. Profile isolation, per-profile navigation retention, incognito exclusion, host exclusions, and credential/medical/financial filtering are covered by tests. Dia's native Settings → Memory view/view model remains in place; its existing On/Off, profile retention, Reset, and Disable/Enable controls are redirected to the local store. Off removes recall/tools and stops future capture/derivation without deleting existing entries; Reset removes browsing/chat/derived entries while retaining connectors.
- Native Apps, live connectors, and Morning Brief are separate compatibility modules. Dia's native Apps view-model state and callbacks are fed local Advanced Chat entitlement and Morning Brief preference while sanitized browser-session connection states are mirrored to the bridge. A direct OAuth/MCP registry implements PKCE, one-use callback state, refresh/revocation, namespaced tool discovery/execution, owner-only tokens, and strict destination allowlists. Morning Brief retains Dia's bundled scheduler, agent, and Report path while adding local profile-exclusive once-daily run tracking.
- Local connector imports, search/query tools, people lookup, and settings UI work with owner-controlled JSON exports.
- Dia's real artifact/report skills and sandboxed file tools reach the selected provider. The bridge deterministically loads `artifact-generation` and `report-kit`, and also adopts a Report when the model itself selects `report-kit` for a broader request. OpenAI-compatible Report `Write` content now streams through Dia's native tool block as the HTML arrives. The bridge withholds `upload_artifact` during creation, constrains retries to native `Write`, and advances only after a successful safe write. A follow-up revision starts a new cycle against the same artifact: Dia first reads the existing HTML, then requires a complete write and successful re-upload, so an earlier upload cannot satisfy a later edit. Blank/root upload paths map to Dia's documented `index.html` behavior; body-only Report Kit revisions regain the required document head and `style.css` link. Visual preflight rejects unresolved Report Kit example URLs, missing local image assets, and uninitialized canvases; diagrams without real media use self-contained inline SVG. The Report Kit's exact Chart.js CDN dependency is localized into the artifact; every other Dia-owned URL remains blocked. Enforcement is scoped to native chat requests with Report tools, so background title/icon/summary jobs cannot inherit and loop on it. Report calls remain gated for path traversal, symlinks, size, file count, and outbound URLs.
- The anonymous-profile gate that skipped Dia's Artifacts controller and the uploader's duplicate official-profile registry check are both structurally patched. Live reflection confirms `ArtifactsDataController` plus its persistence controller initialize through Dia's original setup path. The native tool-safety event carries the exact upload tool ID, and the patched branch targets Dia's unchanged Reports-library continuation.
- Chromium and Dia's per-agent filesystem sandboxes remain enabled. The Codex decision subprocess is additionally confined to an empty read-only workspace with its own action/network facilities disabled.
- Normal browsing and chosen providers remain available. Runtime logs show Segment/LaunchDarkly/Dia telemetry attempts blocked or redirected locally, with no allowed Dia-owned host in the current run.
- Automatic updates are disabled only for the clone. Rebuild-from-official-Dia is transactional, preserves bridge state, and now refuses the source bundle before copying unless its build and all enabled modules appear in the audited manifest.
- Fifteen integrations are declared as independently gated compatibility modules. Runtime modules apply on restart; binary modules require a clean rebuild when disabled. Doctor compares the installed build-module snapshot with the profile configuration. Required identity, network, updater, and local-routing modules fail closed.

## Remaining product work

- **Service-specific connector polish:** the framework and native-session adapters are implemented, but each third-party service that cannot use Dia's browser-local client still needs its own client registration/manifest before a user can authorize it. Incremental-sync hooks exist at the adapter boundary; service-specific delta cursors are not bundled by default. No real Dia account credentials are reused.
- **Morning Brief live window QA:** the native Apps layout and on/off callback were verified in an unlocked session. The first automatic post-5-AM run on this build still needs an elapsed-time pass to confirm Dia's native schedule client delivers the bundled Report end to end.
- **Authenticated browser fetch:** the public fetch override has no access to Chromium cookies. Signed-in page content should continue through native tab-reading context until a cookie-safe local browser-session adapter exists.
- **Future Dia builds:** endpoint, handler, Report, and UI integration points are signature/runtime discovered. Prompt Tools discovery is retained for compatibility research but its private controller remains disabled until a safe native dependency context can be captured. The anonymous account gate still contains a small build-specific ARM64 table, so `./dia-custom update` intentionally leaves the installed clone untouched until a newly released build receives its one-time compatibility audit.
- **Incremental final-text streaming:** reasoning is displayed while providers run, but the bridge buffers a provider's final decision before emitting the final Dia text/tool block. This is required for Codex/Apple structured decisions today and can be optimized independently for OpenAI-compatible streams.

## Account boundary

The Account and Advanced Chat panes cannot become real sync merely by changing feature flags. Dia Custom repurposes only the native Memory toggle as a front end for its independent local SQLite index; this does not enable Dia sync or server summarization. Model identity and service identity remain separate: future OAuth content belongs in the local connector/memory layer, while inference continues through the selected user-controlled provider. No official-Dia account token is copied, decrypted, or synthesized.
